# ماژول کارت‌های ویزیت EMCORE

این ماژول آرشیو مشترک کارت‌های ویزیت شرکت است. هر ورودی مستقل می‌ماند و به جدول
شرکت‌های داخلی یا اشخاص پرسنلی متصل نمی‌شود. مجوز خواندن، همهٔ آرشیو را در اختیار
کاربر قرار می‌دهد؛ create/update/delete مستقل‌اند. فرایند ارجاع یا تأیید وجود ندارد.

## مدل و قواعد

Migration `014_emcore_business_cards.sql` هشت جدول می‌سازد: `emcore_business_cards`
و `emcore_business_card_countries/contact_points/locations/files/source_records/
import_batches/download_log`. ۲۴۹ کشور با نام فارسی و انگلیسی seed می‌شوند؛ مبنای
نام‌ها دادهٔ منطقه‌ای ICU در Node.js زمان تولید migration است. در زمان اجرا اتصال
بیرونی لازم نیست. عضویت در کشور فقط با کد جدول مرجع پذیرفته می‌شود.

کشور ارتباط تجاری از کشور محل نشانی جداست. هر کارت چند راه ارتباطی و نشانی دارد؛
اولین نشانی در ترتیب ثبت، محل اصلی جدول است. مختصات WGS 84، با هفت رقم اعشار،
دقت address/street/city/unknown، توضیح و URL منبع ذخیره می‌شوند. دادهٔ مجهول NULL
است؛ دستهٔ «آفریقا» به کشور ساختگی تبدیل نمی‌شود. شهر فقط از توکن صریح در متن
منبع استخراج می‌شود و مقدار ناشناخته خالی می‌ماند؛ reverse geocoding اجرا نمی‌شود.

هر کارت صفر یا یک تصویر جاری دارد. ستون generated `current_card_id` و کلید یکتای
آن، این قاعده را در دیتابیس تضمین می‌کنند. فقط تصویر اصلی بدون تغییر در مخزن
خصوصی ذخیره می‌شود؛ جدول تصویرها را دریافت نمی‌کند و فقط وضعیت تصویر را نشان
می‌دهد. کلیک دکمه، اصل تصویر را در popup دریافت می‌کند. JPEG/PNG، سقف پیش‌فرض ۱۰ مگابایت
و ۴۰ میلیون پیکسل؛ حافظهٔ لازم پیش از decode نیز کنترل می‌شود. GD و Fileinfo لازم‌اند.
در اسکن رو و پشت، کاربر یک تصویر ترکیبی تهیه می‌کند. ورودی فایل multiple نیست.
Migration `015_emcore_business_cards_original_only.sql` برای نصب‌های قبلی، دو ستون
قدیمی thumbnail را nullable می‌کند؛ مقادیر قبلی برای سازگاری محفوظ‌اند و استفاده
نمی‌شوند. هیچ تصویر کوچک تولید یا دریافت نمی‌شود.

upload روی کارت تصویردار 409 می‌دهد؛ replace فقط برای کارت دارای تصویر جاری
است. جایگزینی، نسخهٔ قبلی را برای ممیزی حفظ می‌کند ولی آن نسخه از API عمومی
نمایش/دانلود ندارد. حذف تصویر، کارت را بدون تصویر می‌کند؛ نسخهٔ قبلی فعال نمی‌شود.
حذف کارت نرم است و دانلود آن را هم می‌بندد. فایل‌های موفق فیزیکی حذف نمی‌شوند؛
فایل‌های عملیات ناموفق پس از rollback پاک می‌شوند.

## ورود اولیه

`tools/build_business_cards_manifest.py` فقط دو Markdown موجود در cart را می‌خواند.
خروجی JSON خصوصی زیر dataset نگه‌داری می‌شود؛ اطلاعات مخاطبان در migration نوشته
نمی‌شوند. تمام متن منبع و مقدارهای مبهم حفظ می‌شوند. متن چندزبانه با layoutهای
بازبینی‌شده استخراج می‌شود؛ نام یا ایمیل حدسی ساخته نمی‌شود. یک تصویر خالی و یک
تصویر ترکیبی چهار کارت، هویت ساخت‌یافته ندارند و همچنان با متن و تصویر محفوظ‌اند.

پوشش منبع: ۴۴۳ رکورد، ۳۰۴ تصویر، ۱۳۹ رکورد بدون تصویر، ۲۹۵ کارت دارای مختصات،
۲۹۷ نقطهٔ مکانی. هر ورودی یک رکورد است؛ تصاویر ترکیبی به چند رکورد شکسته نمی‌شوند.
تمام رکوردهای واردشده ابتدا needs_review هستند. اطلاعات اولیه به معنای تأیید
فعال‌بودن شماره یا سمت فرد نیست.

کلید منبع برای کارت دارای شناسهٔ قدیمی `legacy-card:<id>` و برای مجموعهٔ تصاویر
اولیه `card-image:<relative-path>` است. شمارهٔ عنوان، هویت رکورد نیست.
`export_report.csv` فقط برای lineage تصاویر تکمیلی نگه‌داری می‌شود؛ DELETED در
آن خروجی مانع واردکردن تصویر موجود نمی‌شود. این lineage شامل مسیر خصوصی قدیمی
است و به مرورگر برگردانده نمی‌شود؛ `get` فقط متن Markdown و کلید منبع را نمایش می‌دهد.

Importer CLI با read/create/update کاربر فعال اجرا می‌شود و به‌طور پیش‌فرض dry-run
است. commit هر کارت، منبع و ممیزی را در یک تراکنش ثبت می‌کند. قفل GET_LOCK مانع
اجرای هم‌زمان importer می‌شود. اجرای دوباره، منبع یکسان را skip و منبع تغییریافته
را گزارش می‌کند؛ رکورد حذف‌شده یا ویرایش کاربر بازنویسی/احیا نمی‌شود. اصلاح الگوریتم
استخراج به‌تنهایی باعث بازنویسی کارت‌های قبلی نمی‌شود؛ اصلاح عملیاتی با فرم و ممیزی است.

## API و رابط

Endpoint `/emcore_api/emcore_business_cards.php`؛ همهٔ درخواست‌ها POST و same-origin.
read: `lookups,list,get,duplicate_candidates,preview_image,download_image`.
create: `create`. update: `update,upload_image,replace_image`.
delete: `delete_image,delete`. همهٔ نوشتن‌ها CSRF دارند و actor از نشست گرفته می‌شود.

create و upload/replace شناسهٔ ۳۲رقمی hex `request_id` می‌خواهند. retry باید همان
شناسه و داده را بفرستد؛ پاسخ اول 201 و replay موفق 200 است. شناسهٔ تکراری با دادهٔ
متفاوت 409 می‌دهد. replay تصویر فقط تا وقتی همان فایل جاری است پذیرفته می‌شود.
update/delete/upload/replace/delete_image به `id,lock_version` وابسته‌اند. تعارض 409
است. payload راه‌های ارتباطی `contact_points` و نشانی‌ها `locations`، JSON array
است. جابه‌جایی ترتیب آرایهٔ نشانی‌ها، محل اصلی را عوض می‌کند.

فیلترهای list: `search,business_country_code,location_country,city,related_unit,
has_image,has_coordinates,review_status,record_origin`. boolean filter خالی/0/1 است.
page پیش‌فرض ۱، page_size پیش‌فرض ۲۵ و سقف ۱۰۰. sort_by:
`id,contact_name,organization_name,business_country_code,related_unit,created_at`؛
sort_order: asc/desc. پیش‌فرض id desc. summary و pagination از همان دامنه هستند.

حداقل نام مخاطب یا سازمان برای ثبت جدید لازم است. دادهٔ تاریخی فاقد هویت یا
راه ارتباطی مبهم می‌تواند در ویرایش نامرتبط حفظ شود؛ مقدار جدید ایمیل/وب‌سایت
اعتبارسنجی می‌شود. تلفن‌های چندمقداری یا بازه‌ای نرمال‌شدهٔ جعلی نمی‌گیرند.
تکرار نام+سازمان، شماره/ایمیل نرمال‌شده یا SHA-256 تصویر، فقط هشدار است.

دکمهٔ «نمایش کارت ویزیت» در هر ردیف تصویردار، Modal داخل همان صفحه را باز می‌کند.
کارت بدون تصویر دکمهٔ غیرفعال دارد. تصویر با POST مجاز و Blob URL، بدون برش، در
حدود صفحه نمایش داده می‌شود. خطا در همان پنجره، download اصلی با ثبت لاگ، Escape،
focus trap و بازگشت focus پشتیبانی می‌شوند. خروج از popup، درخواست را لغو و Blob را
آزاد می‌کند. هنگام نمایش از فرم، فرم موقتاً بسته و پس از خروج دوباره باز می‌شود؛
دو focus trap هم‌زمان فعال نمی‌مانند. preview رکورد/نسخه/ممیزی را تغییر نمی‌دهد.

پالت، فونت و Modal مشترک EMCORE مصرف می‌شوند؛ CSS پنل فقط زیر `.emcore-ui` است.
نقشه، OCR، QR، ادغام و ورود جدول قدیمی در v1 پیاده نشده‌اند.

انتخاب کشور تجاری، کشور نشانی و هر دو فیلتر کشور با فیلد پیشنهاد انجام می‌شود.
نام فارسی، انگلیسی و کد دوحرفی قابل جست‌وجو هستند؛ انتخاب با ماوس یا کلیدهای
جهت‌نما و Enter انجام می‌شود. متن انتخاب‌نشده معتبر نیست و در ذخیره‌سازی فقط کد
کشور ارسال می‌شود. پاک‌کردن فیلترها مقدار و اعتبارسنجی فیلد را نیز پاک می‌کند.

## Verification

Fixture مستقل با PHP 8.2، MySQL 8.4، GD، jQuery 1.11.3 و Chrome headless است.
گزارش manifest شامل گروه‌های شباهت و شمارش موارد مبهم است؛ هشدارها هیچ ورودی را
حذف یا ادغام نمی‌کنند. کنترل مستقل fidelity متن کامل هر ۴۴۳ بخش، هش فایل اصلی
هر ۳۰۴ تصویر، هر ۲۹۷ زوج مختصات و سابقهٔ CSV را با manifest تطبیق می‌دهد.
`run_business_cards_fixture.ps1` دیتابیس خالی، seed و retry و آزمون API/مرورگر را
اجرا می‌کند. fixture actor فقط در روتر loopback آزمایشی وجود دارد؛ فایل‌های fixture
نباید روی DocumentRoot واقعی نصب شوند. پذیرش Dynaform و نشست ProcessMaker مقصد
طبق راهنمای استقرار همچنان لازم است.

اجرای 2026-10-06 روی دیتابیس خالی: seed برابر 443/304/139، اجرای دوم new=0،
کنترل fidelity کامل، گزارش یک منبع تغییرکرده بدون نوشتن، ۵۴ بررسی API و ۲۳ بررسی
مرورگر موفق بودند. آزمون شکست ممیزی، حفظ تصویر قبلی و حذف فایل‌های تازهٔ rollback
را هم پوشش داد. تصویر با ابعاد بیش از ۴۰ میلیون پیکسل پیش از decode رد شد.

پس از افزودن فیلد پیشنهاد کشور، مجموعهٔ مرورگر به ۳۰ بررسی موفق گسترش یافت؛
جست‌وجوی فارسی/انگلیسی، انتخاب با کیبورد، حفظ کشور پس از ذخیره، کشور نشانی، reset
و غیرفعال بودن فیلد برای حساب خواندنی نیز بررسی شدند.

پس از حذف بندانگشتی، ۳۱ بررسی مرورگر موفق بود؛ بازشدن جدول هیچ درخواست تصویر
نمی‌فرستد و تصویر اصلی فقط هنگام بازکردن popup خوانده می‌شود. بستهٔ آماده فقط
۳۰۴ فایل اصلی دارد و تطبیق هر ۳۰۴ فایل با API دوباره تأیید شد.
