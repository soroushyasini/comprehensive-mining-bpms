# استقرار ماژول صورت جلسات

کد این ماژول و محیط تست از داده و تنظیمات تولید جدا هستند. migration شماره ۰۱۳ فقط جدول‌ها و دسترسی ماژول جدید را اضافه می‌کند؛ SQL ارسالی شرکت‌ها نباید اجرا یا به جای جدول فعلی وارد شود.

## پیش‌نیاز و ترتیب نصب

۱. از دیتابیس workspace درست و مخزن فایل نسخه پشتیبان بگیرید. پیش‌نیاز migrationهای ۰۰۱ و ۰۰۲، جدول فعلی `emcore_companies` و `USERS` و تابع `shamsi_slash_to_gregorian_date()` است. migrationهای مربوط به ماژول‌های قبلی را دوباره روی تولید اجرا نکنید.

۲. PHP مقصد باید با زیرساخت فعلی EMCORE سازگار باشد و افزونه‌های `pdo_mysql, mbstring, fileinfo, zip` داشته باشد. این تحویل با PHP 8.2 آزموده شده؛ کد از نحو PHP 7.4 نیز استفاده‌پذیر است، اما اجرای واقعی PHP قدیمی‌تر تأیید نشده است. محیط ProcessMaker را صرفاً برای این ماژول به نسخه PHP دیگری ارتقا ندهید.

۳. فایل `database/migrations/013_emcore_meeting_minutes.sql` را با ابزار migration سازمان روی workspace درست اجرا کنید. هیچ `DROP TABLE` یا بازسازی شرکت در این migration وجود ندارد. کدها فقط برای تطبیق یکتا ثبت می‌شوند؛ تنظیمات موجود با اجرای دوباره عوض نمی‌شوند.

۴. یک پوشه خصوصی قابل نوشتن برای PHP، بیرون از **تمام** ریشه‌ها و aliasهای وب ایجاد کنید. نمونه مسیر سازمانی: `C:\pmlearning\emcore-private\meeting-minutes`. همان پوشه را جداگانه همراه دیتابیس پشتیبان‌گیری کنید؛ پشتیبان دیتابیس به‌تنهایی محتوا را حفظ نمی‌کند.

۵. سه فایل `_minutes_domain.php, _minutes_storage.php, emcore_meeting_minutes.php` را در پوشه فعلی `/emcore_api/` قرار دهید. فایل‌های مشترک نشست/مجوز/ممیزی فعلی حفظ شوند.

۶. این تنظیمات را به فایل محلی موجود `emcore_api/emcore_config.php` اضافه کنید؛ فایل تولید را با config.example جایگزین نکنید:

```php
'minutes_storage_root' => 'C:\\pmlearning\\emcore-private\\meeting-minutes',
'minutes_max_upload_bytes' => 52428800,
```

معادل محیطی: `EMCORE_MINUTES_STORAGE_ROOT` و `EMCORE_MINUTES_MAX_UPLOAD_BYTES`. سقف `upload_max_filesize` را حداقل `50M` و `post_max_size` را حداقل `55M` بگذارید؛ هر درخواست فقط یک فایل می‌فرستد. محدودیت وب‌سرور را نیز هماهنگ کنید.

۷. محتوای پوشه `emcore_assets/` شامل پوشه `fonts/` را با همان ساختار به مسیر وب `/emcore_assets/` منتقل کنید. CSS، دو فایل JavaScript و فونت‌ها باید بدون ورود به router یا تغییر محتوا، از همان origin پاسخ دهند. فونت Vazirmatn و مجوز آن همراه فایل‌ها هستند. وابستگی JavaScript به jQuery فعلی ProcessMaker است؛ نسخه جدید jQuery به Dynaform اضافه نکنید.

۸. از پنل `emcore_meeting_minutes_panel.html` در یک Panel WebControl/Dynaform جدید استفاده کنید. همان نشست PHP و origin سایر پنل‌ها را حفظ کنید. نسخه‌های قدیمی پنل‌ها در این استقرار تغییر نمی‌کنند. پس از نصب، Dynaform را با پاک‌سازی cache مرورگر دوباره باز کنید.

۹. مدیران فعال دارای `authorization:update` طبق قرارداد migration دسترسی اولیه می‌گیرند. برای مسئول دفتر read/create/update و در صورت نیاز مسئول حذف، delete بدهید. کاربران فقط‌خواندنی read می‌گیرند. اطلاعات همه شرکت‌ها برای دارندگان read در دسترس خواهد بود.

## کنترل پیش از بهره‌برداری

lint سه فایل PHP و پیکربندی موجود را با PHP **مقصد** اجرا کنید. سپس ابزار فقط‌خواندنی زیر را اجرا کنید؛ web root واقعی را جایگزین کنید:

```powershell
php tools/check_meeting_minutes_deployment.php --web-root=C:\path\to\actual\webroot
node tools/check_meeting_minutes_release.js
```

ابزار deployment وجود جدول‌ها، افزونه‌ها، تبدیل تاریخ، خصوصی‌بودن مخزن و شرکت‌های بدون کد را بررسی می‌کند. آدرس‌ها یا credentialها را چاپ نمی‌کند. نتیجهٔ عدم تطبیق شرکت‌ها به معنی مجوز حدس‌زدن یا تغییر نام آنان نیست؛ با مدیر، شناسه واقعی را تعیین و کد را از تنظیمات پنل وارد کنید. برای HGN، نام دقیق خروجی ارسالی `حفار گستر نائیین` است؛ تفاوت نگارشی ممکن است به تنظیم دستی نیاز داشته باشد.

پذیرش در ProcessMaker واقعی:

- بدون ورود: 401؛ کاربر بدون مجوز: 403؛ کاربر read: نمایش آرشیو و دانلود، بدون نوشتن.
- پنجره تازه تاریخ امروز تهران را نشان دهد؛ بازکردن/بستن شماره مصرف نکند.
- شرکت اول دو شماره پیاپی و شرکت دوم سری مستقل بگیرد؛ کد شرکت بعد از نخستین صدور قفل شود.
- سابقه قدیمی با شماره `43`، بدون تاریخ حدسی ذخیره شود.
- اسکن و پیوست جدا باشند؛ جایگزینی اسکن، نسخه قبلی قابل دانلود را نگه دارد.
- تغییر یک جلسه در دو پنجره، ذخیره روی نسخه قدیمی را با 409 رد کند.
- مخزن، ممیزی، دانلود و حجم فایل روی محیط واقعی کنترل شوند.

## آزمون مستقل قابل تکرار

روی میزبان دارای Docker، Node و Playwright:

```powershell
./tools/run_meeting_minutes_fixture.ps1
```

این runner محیط جدید و مصنوعی MySQL 8.4/PHP 8.2، شبکه اختصاصی و API روی `127.0.0.1:33382` می‌سازد؛ API و دیتابیس آزمایشی به تولید متصل نمی‌شوند. نام‌های fixture از پیش موجود باعث توقف runner می‌شوند و خودکار پاک نمی‌شوند. در پایان فقط containerهایی که خود runner ساخته پاک می‌شوند. گزینه `-KeepRunning` برای بررسی دستی محیط تست است؛ پس از بررسی، فقط `emcore-minutes-test-api` و `emcore-minutes-test-db` را پاک کنید. برنامهٔ fixture و router هرگز روی وب‌سرور تولید نصب نشوند.

Playwright از package محلی یا مسیر `EMCORE_TEST_NODE_MODULES` استفاده می‌کند؛ Chrome نصب‌شده ویندوز نیز پشتیبانی می‌شود. تنظیم اختیاری channel: `EMCORE_TEST_BROWSER_CHANNEL=chrome` یا `msedge`. تصویرهای تست در `output/meeting-minutes/` تولید می‌شوند و دادهٔ آن‌ها مصنوعی است.

## بازگشت و نگه‌داری

در مشکل نصب، پنل جدید را غیرفعال یا از Dynaform خارج و endpoint جدید را از دسترس وب خارج کنید. پنل‌ها و APIهای قبلی باقی می‌مانند. جدول‌ها، شمارنده‌ها، مخزن خصوصی و ممیزی را حذف نکنید. بازگشت به نسخه قبلی ماژول باید با schema فعلی سازگار باشد؛ پاک‌کردن داده rollback محسوب نمی‌شود.

برای پشتیبان‌گیری هماهنگ، نوشتن ماژول را موقتاً متوقف و از دیتابیس و مخزن snapshot بگیرید. نگه‌داری/پاک‌سازی بلندمدت اسناد بر اساس سیاست سازمان انجام شود؛ این نسخه فایل حذف نرم‌شده را فیزیکی پاک نمی‌کند. خطاهای مخزن و خطای تبدیل تاریخ در log سرور بررسی شوند؛ جزئیات exception در مرورگر نمایش داده نمی‌شوند.
