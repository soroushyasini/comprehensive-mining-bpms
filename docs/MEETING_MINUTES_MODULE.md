# ماژول صورت جلسات

این ماژول آرشیو صورت‌جلسات شرکت‌ها را در یک Panel WebControl فارسی نگه‌داری می‌کند. هویت از نشست ProcessMaker و دسترسی از مجوز مشترک `meeting_minutes` گرفته می‌شود. تولید Word، امضای الکترونیکی و گردش تأیید در این نسخه وجود ندارند.

## گردش کار و قواعد

شرکت و مشخصات جلسه در پنجره ثبت انتخاب می‌شوند؛ پیش‌نمایش شماره، شماره‌ای رزرو نمی‌کند. ذخیره موفق، شماره را تخصیص می‌دهد و بخش بارگذاری را باز می‌کند. رکورد فاقد اسکن فعال `awaiting_scan` و رکورد دارای حداقل یک اسکن فعال `archived` است. فایل با نقش `attachment` وضعیت اسکن را تغییر نمی‌دهد. بارگذاری فایل به معنای تأیید محتوای آن یا اصالت امضاها نیست.

`metadata_complete` مستقل از اسکن است. در ثبت عادی، عنوان، شرکت، تاریخ، دستور جلسه و یک رئیس و دبیر حاضر لازم‌اند. ساعت شروع و خاتمه هر کدام اختیاری‌اند و خالی‌بودن آن‌ها اطلاعات سربرگ را ناقص نمی‌کند؛ مقدار نامعلوم `NULL` ذخیره می‌شود. در سابقهٔ قدیمی فقط عنوان، شرکت و شماره اصلی لازم‌اند؛ تاریخ نامعلوم واقعاً `NULL` است. رئیس و دبیر می‌توانند یک فرد باشند؛ یک فرد نمی‌تواند هم حاضر و هم غایب باشد. حداکثر ۳۰۰ فرد برای هر جلسه پذیرفته می‌شود.

اگر شماره یک سند قدیمی دقیقاً با یکی از شماره‌های قالب جدید یکسان باشد، تخصیص خودکار از اولین شماره آزاد ادامه می‌دهد؛ متن سند قدیمی تغییر نمی‌کند. این کنترل هم در پیش‌نمایش و هم در تراکنش ایجاد انجام می‌شود و شماره‌های حذف نرم‌شده را نیز محفوظ می‌داند.

شماره جدید `CODE/YYYY/NNNN` است؛ سال از تاریخ اولیه جلسه گرفته می‌شود. شمارندهٔ هر شرکت/سال مستقل، از یک آغاز و پس از چهار رقم نیز ادامه دارد. شمارنده، قفل کد شرکت، رکورد، افراد و ممیزی در یک تراکنش ذخیره می‌شوند. شماره قدیمی همان متن اصلی است؛ کلید یکتایی آن ارقام فارسی/عربی، فاصله‌ها و حروف ی/ک را یکسان‌سازی می‌کند. شماره در یک شرکت، حتی پس از حذف نرم، قابل استفاده مجدد نیست. شرکت، نوع ثبت و شماره بعد از ایجاد ثابت‌اند؛ اصلاح تاریخ شماره را بازنویسی نمی‌کند.

کدها: امیدکو `EMIDCO`، کاوش گستر امین `KGA`، مس تپه سیاه `TSS`، معدن‌کاران مس میامی `MKM`، تهاتر کالای خراسان `TKK`، میکا `MICA`، Emidco Metal با کد `EMIDCO-METAL` و حفار گستر نائیین `HGN`. migration با شناسه ملی و برای شرکت آخر با نام دقیق، بدون حدس‌زدن شناسه عددی، اتصال را برقرار می‌کند. تطبیق مبهم یا مفقود به‌صورت خودکار انتخاب نمی‌شود. کدهای موجود با اجرای دوباره migration تغییر نمی‌کنند.

## مالکیت داده

| جدول | کاربرد |
|---|---|
| `emcore_meeting_minutes` | مشخصات، شماره، نام و کد تاریخی شرکت، نسخه و شناسه ایجاد |
| `emcore_minutes_company_codes` | کدهای یکتا و قفل پس از نخستین صدور |
| `emcore_minutes_counters` | شماره بعدی هر شرکت و سال |
| `emcore_minutes_participants` | افراد، نام تاریخی، سازمان، حضور و سمت جلسه |
| `emcore_minutes_files` | فایل‌های فعال و نسخه‌های جایگزین‌شده |
| `emcore_minutes_download_log` | سابقه دانلود فایل |
| `emcore_audit_log` | ممیزی تراکنشی مشترک |

شناسه کاربر `USERS.USR_UID` است. نام کاربر جدید از سرور خوانده می‌شود؛ نام ارسالی مرورگر مرجع نیست. در اصلاح جلسه، snapshot افراد قبلی حفظ می‌شود و غیرفعال‌شدن کاربر، انتخاب تاریخی را باطل نمی‌کند. اشخاص بیرونی با نام و سازمان اختیاری ثبت می‌شوند؛ کلید آنان از این دو مقدار ساخته می‌شود. دو فرد بیرونی هم‌نام در یک سازمان، هویت واحد دارند؛ برای تفکیک باید نام ثبت‌شده قابل تمایز باشد.

تاریخ شمسی پس از کنترل روز واقعی و کبیسه، در سرور با الگوریتم تقویم و PHP به میلادی تبدیل می‌شود؛ این ماژول به تابع تبدیل تاریخ در پایگاه داده وابسته نیست. تاریخ امروز از `Asia/Tehran` گرفته می‌شود. ساعت `HH:MM` است؛ خاتمهٔ قبل از شروع فقط با `ends_next_day=1` پذیرفته می‌شود.

هر ساعت می‌تواند مستقل خالی باشد؛ وقتی هر دو وارد شده‌اند ترتیب آن‌ها بررسی می‌شود. انتخاب «خاتمه در روز بعد» نیازمند هر دو ساعت است. شاخص کامل‌بودن سوابق قدیمی هنگام ذخیرهٔ ویرایش دوباره محاسبه می‌شود.

## قرارداد API

Endpoint: `/emcore_api/emcore_meeting_minutes.php`؛ همه درخواست‌ها POST هستند. پاسخ موفق `success` و `data` دارد؛ خطا از پوش مشترک EMCORE و کدهای HTTP آن استفاده می‌کند.

| Action | دسترسی | ورودی/خروجی اصلی |
|---|---|---|
| `lookups` | read | شرکت‌ها، تاریخ تهران، مخزن، محدودیت فایل، مجوز و CSRF |
| `search_users` | read | `search`؛ حداکثر ۳۰ کاربر فعال با نام و نام کاربری |
| `search_participants` | read | `search`؛ افراد آرشیو فعال، شامل افراد بیرونی |
| `number_preview` | read | `company_id, meeting_date_fa`؛ شماره پیشنهادی و `provisional=true` |
| `list` | read | فیلتر، مرتب‌سازی، صفحه‌بندی و خلاصه از دامنه مشترک |
| `get` | read | `id`؛ مشخصات، افراد و فایل‌های فعال/نسخه‌های قبلی |
| `create` | create + CSRF | مشخصات، `company_id, record_origin, request_id` و برای legacy، `meeting_number` |
| `update` | update + CSRF | `id, lock_version` و مشخصات قابل اصلاح |
| `upload_file` | update + CSRF | multipart: `id, lock_version, file_role, request_id, file` |
| `replace_file` | update + CSRF | همان ورودی، به‌علاوه `file_id, replacement_reason`؛ فقط scan |
| `download_file` | read | `file_id`؛ فایل و ثبت لاگ، شامل نسخه قبلی جایگزین‌شده |
| `delete_file` | delete + CSRF | `id, file_id, lock_version`؛ حذف نرم و تغییر نسخه جلسه |
| `delete` | delete + CSRF | `id, lock_version`؛ حذف نرم جلسه |
| `set_company_code` | authorization:update + CSRF | `company_id, code`؛ کد ۲ تا ۳۲ کاراکتر لاتین بزرگ/عدد/خط تیره |

مشخصات قابل اصلاح: `title, meeting_date_fa, start_time, end_time, ends_next_day, agenda, notes, participants`. فهرست `participants` یک JSON array است؛ هر عضو `usr_uid` یا `name_snapshot` و `organization_snapshot` بیرونی، `attendance=present|absent` و پرچم‌های `is_chair, is_secretary` دارد. پاسخ `person_key` را نیز برای فیلتر و هویت تاریخی برمی‌گرداند.

فیلترهای فهرست: `search, company_id, date_from, date_to, person_key, record_origin, scan_status, metadata_complete`. بازه تاریخ شامل دو انتهاست و تاریخ نامعلوم با فیلتر بازه وارد نتیجه نمی‌شود. `page_size` حداکثر ۱۰۰ و پیش‌فرض ۲۵ است. `sort_by` یکی از `id, meeting_date_en, meeting_number, title, company_name_snapshot, chair_name, secretary_name, scan_count, attachment_count` و جهت `asc|desc` است؛ پیش‌فرض `id desc`. مرتب‌سازی شماره متنی است، زیرا شماره‌های قدیمی الزاماً عددی نیستند.

`request_id` یک مقدار تصادفی ۳۲کاراکتری hex است. برای retry ایجاد و بارگذاری، همان شناسه و payload قبلی ارسال شود. ارسال دوباره نتیجه همان رکورد/فایل را با HTTP 200 بازمی‌گرداند؛ بار اول HTTP 201 است. استفاده دوباره از شناسه با payload متفاوت خطای 409 می‌دهد. بررسی replay پیش از کنترل `lock_version` انجام می‌شود تا پاسخ گم‌شده موجب ثبت دوباره نشود. هر فایل صف، شناسه مستقل خود را دارد؛ بعد از موفقیت، نسخه جدید جلسه برای فایل بعدی استفاده می‌شود.

## فایل، تاریخچه و امنیت

اسکن `pdf,jpg,jpeg,png`؛ پیوست `doc,docx,pdf,xls,xlsx,jpg,jpeg,png,zip`. سقف پیش‌فرض هر فایل ۵۰ مگابایت است. MIME عمومی برای اسکن پذیرفته نمی‌شود. تصویر با `getimagesize`، سرآیند PDF و ساختار ZIP/Office نیز کنترل می‌شوند؛ این کنترل‌ها جایگزین آنتی‌ویروس یا تأیید امضا نیستند. ZIP استخراج نمی‌شود.

فایل بیرون از web root، با نام تصادفی و SHA-256 نگه‌داری می‌شود. download فقط پس از مجوز، کنترل جلسه/فایل و صحت hash انجام می‌شود. مسیر مخزن در JSON قرار نمی‌گیرد. فایل superseded از تاریخچه قابل دانلود است؛ فایل حذف نرم‌شده یا فایل جلسه حذف‌شده قابل دانلود نیست. جایگزینی اسکن قدیمی را حفظ می‌کند؛ حذف آخرین اسکن فعال، وضعیت جلسه را به انتظار اسکن بازمی‌گرداند و نسخه قبلی خودکار فعال نمی‌شود.

نام/کد شرکت و نام افراد snapshot هستند؛ تغییر یا حذف نرم شرکت، آرشیو را ناپدید نمی‌کند. lookup فقط اطلاعات لازم را برمی‌گرداند و به مجوز ماژول شرکت‌ها وابسته نیست. دارندهٔ read همه شرکت‌ها را می‌بیند؛ تفکیک دسترسی شرکتی در این نسخه وجود ندارد.

## بررسی‌های اجراشده

آزمون مستقل با PHP 8.2، MySQL 8.4 و Chrome/Chromium روی jQuery 1.11.3 انجام شده است. اسکریپت‌ها و سناریوهای ثبت هم‌زمان، retry، rollback ممیزی، فایل، snapshot، فیلتر، XSS، صفحه‌کلید و موبایل در `tools/test_meeting_minutes_*` قرار دارند. نصب در Dynaform واقعی، اشتراک نشست و نسخه PHP مقصد باید طبق راهنمای استقرار پذیرفته شوند.
