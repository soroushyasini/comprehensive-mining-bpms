# نشان‌شده‌های شخصی و پیوست‌های فشرده

## رفتار پنل

کنار هر ردیف یک قلب قرار دارد. انتخاب آن، فراخوان را در تب «نشان‌شده‌های من» برای همان کاربر نگه می‌دارد. با انتخاب دوباره، نشان برداشته می‌شود. نشان‌ها در دیتابیس ذخیره می‌شوند و با خروج از حساب یا بستن مرورگر از بین نمی‌روند.

نشان شخصی با وضعیت تجاری «علاقه‌مند» تفاوت دارد: وضعیت، نسخهٔ رکورد، تصمیم مدیر، کارتابل و اعلان‌ها را تغییر نمی‌دهد. مدیر و اپراتور نشان‌های مستقل دارند و فقط رکوردهای داخل دامنهٔ دسترسی خود را می‌توانند نشان کنند. این امکان به مجوز خواندن ماژول نیاز دارد و در حالت غیرفعال‌بودن گردش کار نیز قابل استفاده است.

در تب نشان‌شده‌ها، جست‌وجو، تاریخ، مرتب‌سازی، صفحه‌بندی و خروجی اکسل حفظ می‌شوند. نمای کارتابل در این تب اعمال نمی‌شود تا نشان‌های شخصی به صف بررسی یا مرحلهٔ پیگیری محدود نشوند. سایر فیلترها همچنان اعمال می‌شوند؛ خروجی اکسل همهٔ نتایج همان جست‌وجو را می‌گیرد، نه فقط صفحهٔ جاری.

## فایل‌های فشرده

ZIP از قبل مجاز بود؛ RAR نیز به مدارک اصلی فراخوان، فایل ارسال نهایی و پیوست اقدامات اضافه شده است. کتابخانهٔ جدیدی روی سرور لازم نیست. تنظیمات مخزن خصوصی و محدودیت اندازه تغییری نکرده‌اند؛ مجموع پیوست‌های هر اقدام همچنان حداکثر ۵۰ مگابایت است.

سرور پسوند، MIME و امضای ابتدای ZIP و RAR را بررسی می‌کند. امضای هر دو قالب RAR مطابق [مستندات رسمی RAR](https://www.rarlab.com/technote.htm) شناسایی می‌شود. فایل‌ها استخراج یا اجرا نمی‌شوند؛ بررسی امضا جایگزین اسکن بدافزار یا بررسی سلامت کامل آرشیو نیست. فایل اجرایی خوداستخراج‌شونده پشتیبانی نمی‌شود.

## استقرار

ابتدا از دیتابیس پشتیبان بگیرید و migration زیر را اجرا کنید. این migration مستقل از فعال‌بودن گردش کار، برای پنل و API جدید لازم است؛ جدول موجود یا رکوردهای فراخوان را تغییر نمی‌دهد و اجرای دوبارهٔ آن جدول تکراری نمی‌سازد.

```text
database/migrations/016_emcore_procurement_favorites.sql
```

سپس این دو فایل را در پوشهٔ API سرور به‌روز کنید:

```text
emcore_api/emcore_procurement_notices.php
emcore_api/_procurement_storage.php
```

نسخهٔ جدید `panels/emcore_procurement_notices_panel.html` را نیز مانند قبل در پنل ProcessMaker جایگزین کنید. تنظیمات خصوصی سرور را بازنویسی نکنید. برای این تغییر، نصب دوبارهٔ فرایند یا تغییر Triggerها لازم نیست.

## قرارداد و کنترل

عملیات `set_favorite` با `id` و مقدار صریح `is_favorite=1` یا `is_favorite=0` اجرا می‌شود. هویت از نشست جاری گرفته می‌شود، نه ورودی درخواست. عملیات به CSRF نیاز دارد و تکرار آن نشان تکراری نمی‌سازد. پاسخ‌های فهرست و رکورد، `is_favorite` کاربر جاری را دارند؛ فیلتر `favorites_only=1` فقط نشان‌های همان کاربر را برمی‌گرداند.

```cmd
php -n tools\test_procurement_uploads.php
node tools\check_procurement_favorites_release.js
node tools\check_procurement_notices_release.js
node tools\check_procurement_workflow_release.js
node tools\check_procurement_analytics_release.js
```

آزمون‌های یکپارچه و مرورگر موجود نیز نشان‌کردن شخصی، تکرار درخواست، حذف نشان، فیلتر، ماندگاری، صفحه‌کلید و بارگذاری و دانلود آرشیو را پوشش می‌دهند. فایل‌های `tools/fixtures` فقط برای آزمون محلی‌اند و نباید در مسیر عمومی سرور قرار بگیرند.
