# سوابق پیگیری معادن

سوابق دستی و دسته‌بندی‌شده به شناسهٔ معدن متصل هستند. دسته‌ها بین تمام معادن مشترک‌اند؛ هیچ گمانه، پروندهٔ ProcessMaker یا گزارش حفاری به‌صورت خودکار ساخته یا وارد نمی‌شود.

## نصب

۱. از دیتابیس و فایل‌های فعلی پنل/API پشتیبان بگیرید. پیش‌نیازها: جدول موجود `emcore_mines` با کلید `INT UNSIGNED`، کاربران ProcessMaker، مجوزها و ممیزی مهاجرت‌های ۰۰۱ و ۰۰۲. در `information_schema` نوع و موتور جدول معدن را بررسی کنید؛ مهاجرت در صورت ناسازگاری کلید خارجی باید متوقف شود.

۲. مهاجرت `database/migrations/019_emcore_mine_history.sql` را پیش از انتشار API معادن اجرا کنید. چهار جدول جدید و سه دستهٔ اولیه می‌سازد؛ اجرای مجدد دسته‌ها را تکثیر یا تنظیمات قبلی را بازنشانی نمی‌کند. جداول پایهٔ معادن را ایجاد نمی‌کند.

۳. پوشه‌ای خصوصی، قابل‌نوشتن برای PHP و خارج از تمام مسیرهای وب ایجاد کنید. متغیر `EMCORE_MINE_HISTORY_STORAGE_ROOT` یا کلید `mine_history_storage_root` در تنظیمات محلی را تنظیم کنید. سقف پیش‌فرض هر فایل ۲۰ MiB است؛ `EMCORE_MINE_HISTORY_MAX_UPLOAD_BYTES` / `mine_history_max_upload_bytes` فقط می‌تواند این سقف را کاهش دهد. تنظیمات PHP برای `upload_max_filesize` حداقل `20M` و `post_max_size` حداقل `22M` باشد. هر درخواست یک فایل می‌فرستد. افزونه‌های `pdo_mysql`، `mbstring`، `fileinfo` و `zip` لازم‌اند. نبود مخزن، مشاهده و ثبت بدون پیوست را مسدود نمی‌کند.

۴. بستهٔ هماهنگ API را منتشر کنید: `_mine_history_domain.php`، `_mine_history_storage.php`، `emcore_mine_history.php` و نسخهٔ جدید `emcore_mines.php`. کد مشترک `_bootstrap.php`، `_audit.php` و `_module_permissions.php` باید در همان پوشه باشد.

۵. فایل‌های `mine-history.js` و `mine-history.css` همراه نسخهٔ موجود `emcore-ui.js`، `emcore-ui.css` و فونت‌های مشترک را در `/emcore_assets` منتشر کنید. محتوای `panels/emcore_mines_panel.html` را در Panel WebControl جایگزین کنید. jQuery همان نسخهٔ میزبان است؛ کتابخانهٔ خارجی جدیدی لازم نیست. پس از انتشار، فرم را با پاک‌سازی کش باز کنید.

اصلاح هماهنگی فایل‌ها: نسخهٔ `20261105-2` در لینک‌های CSS/JS پنل ثبت شده است. JavaScript پیش از بازکردن سوابق، نشان نسخهٔ CSS را بررسی می‌کند؛ اگر فایل قدیمی باشد، CSS را با نشانی نسخه‌دار دوباره می‌گیرد. اگر نسخهٔ جدید در سرور وجود نداشته باشد یا دریافت نشود، پیام روشن نمایش داده می‌شود و پنجرهٔ خراب باز نمی‌شود. برای نصب این اصلاح، هر دو فایل assets و محتوای پنل معادن را به‌روز کنید تا JavaScript قدیمی نیز از کش خارج شود. تغییر دیتابیس لازم نیست. در تغییرهای بعدی ظاهر، نشان `--mh-asset-version`، مقدار `assetVersion` و نسخهٔ لینک‌های پنل باید هم‌زمان به‌روز شوند.

## دسترسی و قرارداد API

تمام درخواست‌ها POST و با نشست فعلی ProcessMaker هستند. `mines:read` برای همهٔ عملیات لازم است. ایجاد سابقه، دسته و پیوست به `mines:create`؛ ویرایش سابقه و دسته به `mines:update`؛ حذف نرم سابقه و پیوست به `mines:delete` نیاز دارد. تمام تغییرها CSRF می‌خواهند. دانلود یک خواندن مجاز است و CSRF تغییر را لازم ندارد. هیچ مجوز تازه‌ای اضافه یا خودکار اعطا نمی‌شود.

مسیر API: `/emcore_api/emcore_mine_history.php`.

| عملیات | ورودی اصلی | خروجی |
|---|---|---|
| `lookups` | بدون شناسهٔ معدن | دسته‌ها، مجوزها، CSRF، امروز تهران به میلادی، آمادگی مخزن، سقف‌ها و پسوندها |
| `summary` | `mine_id` | نام معدن و دسته‌های دارای سابقه همراه تعداد |
| `list` | `mine_id, category_id, offset` | حداکثر ۲۵ سابقه، `has_more, next_offset` |
| `get` | `mine_id, id` | سابقه و فایل‌های قابل مشاهده |
| `create` | `mine_id, category_id, description, executed_on_fa, request_id` | `data` سابقه؛ وضعیت ۲۰۱ یا ۲۰۰ برای تکرار همان درخواست |
| `update` | همان فیلدهای محتوا، `id, lock_version` | سابقه با نسخهٔ جدید |
| `delete` | `mine_id, id, lock_version` | حذف نرم |
| `upload` | multipart: `mine_id, id, lock_version, request_id, file` | اطلاعات عمومی فایل و `lock_version` جدید سابقه |
| `download` | `mine_id, id, file_id` | جریان فایل با نام اصلی و ثبت دانلود |
| `delete_file` | `mine_id, id, file_id, lock_version` | حذف نرم و افزایش نسخهٔ سابقه؛ برای ادامه `get` فراخوانی شود |
| `category_create` | `title, sort_order, is_active` | دستهٔ جدید |
| `category_update` | فیلدهای دسته، `id, lock_version` | دسته با نسخهٔ جدید |

شناسهٔ درخواست ۳۲ نویسهٔ hex تصادفی است؛ کلید تکرار در محدودهٔ کاربر یکتا است. همان درخواست با محتوای متفاوت یا پس از حذف رکورد، خطای ۴۰۹ می‌دهد. در تکرار بارگذاری، نسخهٔ فعلی سابقه برمی‌گردد. ویرایش با نسخهٔ قدیمی خطای ۴۰۹ دارد؛ کاربر باید رکورد را بازخوانی کند. درخواست‌ها، از جمله دانلود و فایل، وجود و حذف‌نشدن معدن و تعلق سابقه و فایل به آن را کنترل می‌کنند.

## رفتار داده و خطا

- در پنجرهٔ مشاهده، مشخصات ثبت در نوار مجزا نمایش داده می‌شود. تاریخ ثبت به شمسی تبدیل می‌شود و ساعت ذخیره‌شده بدون تغییر منطقهٔ زمانی مرورگر باقی می‌ماند. پیوست‌ها در یک‌سوم سمت چپ و متن در سمت راست هستند؛ در موبایل پیوست‌ها زیر متن قرار می‌گیرند. آیکن‌های ویرایش و حذف نام دسترس‌پذیر و راهنمای متنی دارند. این تغییر نمایشی فقط به `mine-history.js` و `mine-history.css` نیاز دارد و مهاجرت جدیدی ندارد.
- هر سابقه کادر مستقل دارد و عملیات ویرایش و حذف داخل نوار مشخصات قرار می‌گیرد. لیست پیوست‌ها حداکثر ۲۶۰ پیکسل ارتفاع دارد؛ عنوان و تعداد بیرون از محدودهٔ اسکرول می‌مانند. نام فایل تا دو خط نمایش داده می‌شود و نام کامل در راهنما و نام دسترس‌پذیر دکمه باقی می‌ماند. برای فهرست بلند، راهنمای اسکرول نمایش داده می‌شود و حرکت با صفحه‌کلید نیز ممکن است. فهرست کوتاه ارتفاع طبیعی خود را حفظ می‌کند.
- تاریخ اجرا الزامی و حداکثر امروز تهران است. تاریخ شمسی با اعداد فارسی، عربی یا لاتین پذیرفته و روی سرور اعتبارسنجی و تبدیل می‌شود؛ تابع تقویم SQL لازم نیست. تاریخ ثبت و اجرا مستقل‌اند.
- شرح حداکثر ۵۰۰۰ نویسه است و به‌صورت متن نمایش داده می‌شود. ترتیب سوابق: تاریخ اجرا، زمان ثبت و شناسه، همگی نزولی. دسته‌ها با ترتیب تنظیم‌شده و سپس شناسه مرتب می‌شوند. دسته‌های غیرفعال در آرشیو باقی می‌مانند و تنها حفظ دستهٔ قبلی در ویرایش مجاز است.
- فایل‌های PDF، DOC/DOCX، XLS/XLSX و JPEG/PNG با بررسی پسوند، MIME و ساختار متناسب پذیرفته می‌شوند. سقف ۱۰ فایل فعال با قفل رکورد کنترل می‌شود. مسیر و هش خصوصی در پاسخ‌های عادی نمایش داده نمی‌شوند.
- سابقه پیش از صف پیوست‌ها ذخیره می‌شود. شکست فایل باعث بازگرداندن فایل‌های موفق نمی‌شود؛ صف از فایل ناموفق با همان شناسه ادامه می‌دهد. تا پایان صف، فیلدهای محتوا ثابت می‌مانند. خروج با فایل باقی‌مانده هشدار دارد. افزودن فایل به سابقهٔ موجود، از فرم ویرایش برای کاربران دارای مجوز ویرایش و ایجاد ممکن است.
- همهٔ تغییرات با ممیزی تراکنشی هستند. شکست ممیزی فایل تازه را از مخزن پاک و تغییر دیتابیس را rollback می‌کند. حذف نرم فایل/سابقه بایت‌های خصوصی را پاک نمی‌کند. پشتیبان دیتابیس و مخزن باید هماهنگ باشد.
- ایجاد سابقه، تغییرات فایل و حذف معدن، ابتدا ردیف معدن را قفل می‌کنند. معدن دارای سابقهٔ حذف‌نشده قابل حذف نیست. نسخهٔ قدیمی API معادن نباید کنار این قابلیت منتشر بماند.

## آزمون و بازگشت

تست مستقل تاریخ و اعتبارسنجی: `php tools/test_mine_history_domain.php`.

آزمون متمرکز نمای سوابق با API شبیه‌سازی‌شده: `node tools/test_mine_history_viewer.js`. مسیر یک نسخهٔ محلی jQuery را با `EMCORE_TEST_JQUERY` مشخص کنید؛ در محیط توسعهٔ فعلی از کش fixture استفاده می‌شود. این آزمون چیدمان دسکتاپ و موبایل، نام‌های بلند فایل، تاریخ شمسی مستقل از منطقهٔ زمانی مرورگر، مجوزها و عملکرد آیکن‌ها را کنترل می‌کند.

اجرای کامل با Docker، Node و Playwright: `./tools/run_mine_history_fixture.ps1`. این راه‌انداز MySQL 8.4 و PHP را به‌صورت یک‌بارمصرف بالا می‌آورد و در پایان متوقف و پاک می‌کند. برای بازرسی دستی می‌توان از `-KeepRunning` استفاده کرد.

آزمون HTTP: `node tools/test_mine_history_integration.js`؛ آزمون مرورگر: `node tools/test_mine_history_browser.js`. این دو تنها به محیط یک‌بارمصرف روی `127.0.0.1:33388` متصل می‌شوند و به‌ترتیب روی fixture تازه اجرا می‌شوند. راه‌انداز باید `EMCORE_MH_FIXTURE=1`، دیتابیس خالی با نام دقیق `emcore_mine_history_fixture` و تنظیمات خصوصی آزمایشی داشته باشد. `tools/fixtures/mine_history/setup.php` فقط CLI و دیتابیس آزمایشی خالی را قبول می‌کند. router آزمایشی هرگز روی سرور عملیاتی نصب نشود. پس از آزمون‌ها، fixture و سرویس‌هایش متوقف شوند. بررسی `verify.php` در همان پوشه، پوشش ممیزی، ثبت دانلود و نبود فایل بدون رکورد را کنترل می‌کند.

پذیرش نهایی در Dynaform واقعی: نشست ProcessMaker، کاربران با مجوزهای متفاوت، ثبت و نمایش سابقه، تقویم، پیوست، جابه‌جایی فوکوس، اندازهٔ موبایل و فرم فعلی معدن بررسی شوند. اجرای آزمون جدا، جای این پذیرش را نمی‌گیرد.

اعتبارسنجی محلی این تغییر با PHP 8.3، MariaDB 10.11 و مرورگر Chrome انجام شده است. راه‌انداز Docker برای اجرای همان مجموعه روی MySQL 8.4 آماده است؛ اجرای آن و پذیرش روی سرور واقعی ProcessMaker در این محیط انجام نشده است.

برای بازگشت، کل بستهٔ پنل و API را به نسخهٔ قبلی برگردانید و جدول‌ها و مخزن را حفظ کنید. جدول‌ها را DROP نکنید. در دورهٔ بازگشت، ورود به قابلیت جدید متوقف است؛ حذف معادن دارای سوابق جدید نیز باید از نظر عملیاتی متوقف بماند، چون API قدیمی از این وابستگی خبر ندارد.
