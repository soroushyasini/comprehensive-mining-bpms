# ورود بستهٔ آمادهٔ کارت‌های ویزیت

این بسته مستقیماً از دو فایل Markdown پوشهٔ cart ساخته شده است. شامل ۴۴۳ کارت،
۳۰۴ اصل تصویر و ۱۳۹ کارت بدون تصویر است. ۲۹۵ کارت دارای مختصات
هستند و هر ۲۹۷ زوج مختصات حفظ شده‌اند. اصل تصاویر بدون تغییر کپی شده‌اند.

## فایل‌ها و پوشه‌ها

```text
business_cards_import_2026-10-07/
  IMPORT.sql
  business_cards_table.csv
  manifest.json
  SHA256SUMS.txt
  README_FA.md
  business_cards_storage/
    <32-hex>.jpg
    ...
```

`IMPORT.sql` فایل ورود به دیتابیس است؛ جدول‌های ماژول و کشورها را نیز آماده می‌کند.
CSV برای بازبینی است: یک ردیف برای هر کارت و ستون نام/مسیر attachment دارد.
نام فارسی کشور، تلفن‌ها، ایمیل‌ها، نشانی‌ها و مختصات هم در ستون‌های مستقل آمده‌اند.
مقادیر CSV که با علامت فرمول شروع می‌شوند، برای نمایش متنی در Excel با پیشوند
apostrophe ذخیره شده‌اند؛ SQL مقدار اصلی را حفظ می‌کند.
برای ورود عملیاتی، SQL را استفاده کنید؛ واردکردن CSV به یک جدول تازه، ارتباط‌های
مورد انتظار API را ایجاد نمی‌کند. چند تلفن یا چند نشانی در جداول وابسته ثبت می‌شوند.
متن اصلی منابع و سابقهٔ CSV در source_records نگه‌داری می‌شوند.

## نصب در سرور

۱. از دیتابیس مقصد پشتیبان بگیرید. دیتابیس همان workspace نصب ProcessMaker باشد.
بنیان EMCORE، شامل USERS و migrations 001/002، باید قبلاً نصب باشد. حساب ورود SQL
به مجوز ساخت جدول، جدول موقت و CREATE ROUTINE/EXECUTE نیاز دارد. روی MySQL 5.7+
با InnoDB/utf8mb4 اجرا می‌شود؛ آزمون بسته با MySQL 8.4 انجام می‌شود.

۲. در ابتدای IMPORT.sql عبارت `REPLACE_WITH_ACTIVE_USER_UID` را با UID سی‌ودوحرفی
یک کاربر ACTIVE واقعی ProcessMaker جایگزین کنید. همین کاربر به‌عنوان عامل ورود
اولیه و ممیزی ثبت می‌شود. بسته کاربر یا مجوز عمومی ایجاد نمی‌کند.

UID نام کاربری نیست. برای پیدا کردن آن در همان دیتابیس اجرا کنید:

```sql
SELECT USR_UID, USR_USERNAME, USR_FIRSTNAME, USR_LASTNAME
FROM USERS WHERE USR_STATUS='ACTIVE';
```

اگر در CALL خطای 1644 مربوط به import_actor دیده شد، کارت‌ها هنوز وارد نشده‌اند.
در همان اتصال، ابتدا `SET @emcore_bc_import_actor = 'UID واقعی';` و سپس CALL همان
procedure را اجرا کنید. متغیر نشست در اتصال دیگر باقی نمی‌ماند؛ SET و CALL را
با هم اجرا کنید. همچنین می‌توانید UID را در خط SET ابتدای فایل جایگزین و کل فایل
را مجدداً ایمپورت کنید. تعیین مقدار مستقیم، مقدار نمونهٔ تلاش قبلی را بازنویسی می‌کند.

در نصب دارای ساختار قدیمی، پیش از اجرای مجدد CALL باید migration 015 اعمال شود.
CALL فقط داده‌ها را وارد می‌کند و تغییر ساختار ابتدای فایل را اجرا نمی‌کند. خطای
1364 مربوط به thumbnail_filename با دستور زیر رفع می‌شود:

```sql
ALTER TABLE emcore_business_card_files
  MODIFY COLUMN thumbnail_filename VARCHAR(80) NULL DEFAULT NULL,
  MODIFY COLUMN thumbnail_sha256 CHAR(64) NULL DEFAULT NULL;
```

این دستور فقط ستون‌های قدیمی را اختیاری می‌کند؛ داده‌ها و اصل تصاویر حذف نمی‌شوند.
سپس SET مربوط به UID واقعی و CALL همان procedure را در همان اتصال اجرا کنید.

۳. **فقط پوشهٔ business_cards_storage را** به مسیر خصوصی خارج از web root منتقل
کنید؛ مثلاً `/srv/emcore-private/business_cards_storage`. تمام ۳۰۴ فایل را یکجا کپی
کنید. پس از انتقال، نام هیچ فایل را تغییر ندهید. فرایند PHP باید دسترسی خواندن و
برای بارگذاری‌های بعدی دسترسی نوشتن داشته باشد.

۴. در تنظیمات خصوصی موجود `emcore_api/emcore_config.php` فقط این کلید را تعیین کنید:

```php
'business_cards_storage_root' => '/srv/emcore-private/business_cards_storage',
```

در Windows مسیر واقعی را وارد کنید، مثلاً `F:/emcore-private/business_cards_storage`.
اگر `EMCORE_BUSINESS_CARDS_STORAGE_ROOT` در محیط سرور تنظیم است، بر فایل اولویت
دارد و باید به همان پوشه اشاره کند. API به تغییر مسیر یا ساختار تازه نیاز ندارد؛
نام فایل اصلی را از emcore_business_card_files می‌خواند. تصویر هنگام کلیک روی
«نمایش کارت ویزیت» دریافت می‌شود؛ جدول هیچ تصویر یا بندانگشتی بارگذاری نمی‌کند.

۵. IMPORT.sql را در همان دیتابیس ایمپورت کنید؛ مثلاً از Import در phpMyAdmin یا
mysql client. در phpMyAdmin اندازهٔ مجاز فایل SQL را کنترل کنید. ورود داده در یک
تراکنش اجرا می‌شود؛ خطا آن را rollback می‌کند. procedure کمکی پس از موفقیت حذف
می‌شود. اجرای دوبارهٔ همین فایل روی منابع یکسان، دادهٔ کاربر را بازنویسی نمی‌کند.
اگر CLI قدیمی قبلاً منابع را وارد کرده باشد، source_key یکسان دوباره وارد نمی‌شود؛
در آن حالت تصاویر جاری قبلی باید در همان مخزن محفوظ باشند. فایل‌های قبلی مخزن
را پاک یا جایگزین نکنید و پوشهٔ آماده را با آن ادغام کنید.

۶. برای پذیرش پیش از ثبت دستی، شمارش کارت‌ها ۴۴۳، تصویرهای جاری ۳۰۴ و منابع ۴۴۳
باشد. اجرای دوم باید imported_cards=0 و skipped_cards=443 بدهد. فایل SQL، CSV و
manifest را در مسیر عمومی قرار ندهید؛ فقط پوشهٔ تصاویر در مخزن خصوصی لازم است.
مجوز business_cards کاربران و نصب پنل/API مطابق راهنمای اصلی ماژول انجام می‌شود.

```sql
SELECT COUNT(*) FROM emcore_business_cards WHERE deleted_at IS NULL;
SELECT COUNT(*) FROM emcore_business_card_files WHERE current_card_id IS NOT NULL;
SELECT COUNT(*) FROM emcore_business_card_source_records;
SELECT COUNT(DISTINCT card_id) FROM emcore_business_card_locations WHERE latitude IS NOT NULL;
SELECT COUNT(*) FROM emcore_business_card_locations WHERE latitude IS NOT NULL;
```

## تطبیق و حفظ سابقه

نام‌های همسان مانند `1.jpg` در پوشه‌های مختلف به نام‌های تصادفی سی‌ودوحرفی تبدیل
شده‌اند. در CSV، source_key، مسیر قدیمی، نام فایل جدید و هش اصل تصویر برای تطبیق
آمده‌اند. فقط اصل تصویر به همان رکورد فایل وصل است؛ کارت بدون تصویر فایل وابسته
ندارد. SHA256SUMS.txt صحت فایل‌ها را کنترل می‌کند. نام پوشهٔ اصلی روی سرور می‌تواند
تغییر کند؛ فقط ریشهٔ تنظیمات باید درست باشد. مسیرهای محلی F: داخل دیتابیس ذخیره
نمی‌شوند و دسته‌بندی فارسی پوشه‌های قدیمی برای API لازم نیست.

بسته برای ورود اولیهٔ منابع است؛ جایگزینی تصاویر یا انتقال ویرایش‌های کاربران
از یک نصب دیگر نیست. منبع تغییرکرده با کلید قبلی باعث توقف و گزارش نیاز به بررسی
می‌شود. داده‌های مشابه ادغام نمی‌شوند و موارد مبهم برای بررسی محفوظ‌اند.

کنترل checksum فایل SQL را پیش از جایگزینی UID انجام دهید؛ تغییر عمدی UID هش SQL
را تغییر می‌دهد و اثری بر هش تصاویر ندارد.

آزمون بستهٔ 2026-10-07 روی MySQL 8.4 و PHP 8.2: شمارش ۴۴۳/۳۰۴/۱۳۹، اجرای دوباره
با صفر رکورد جدید، حفظ ویرایش کاربر، rollback در شکست ممیزی و توقف منبع تغییرکرده
موفق بود. API اصل تصویر هر ۳۰۴ کارت را با هش صحیح خواند و دانلود لاگ شد.

SQL این نسخه، تغییر سازگاری migration 015 را نیز شامل می‌شود. دو ستون thumbnail
قدیمی صرفاً برای سازگاری nullable هستند؛ بسته و رکوردهای جدید هیچ بندانگشتی ندارند.
